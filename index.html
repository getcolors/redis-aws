DEPLOYMENT · AWS · REDIS

redis-aws

Desired state for one Redis 7.2 server on one AWS EC2 instance in us-east-1, converged by the redis Package Skill: loopback only, an SSH tunnel as the client path, an append-only file for persistence, and RDB backup sets in a deployment-owned S3 bucket with a rehearsed restore.

Desired state only. This repository is a colors.yml, three installed launchers, an .envrc and a devenv.nix. Everything else is generated under .colors/ or secret in .envrc.private.

Use

Pick ./green, ./red or ./blue; all three converge the same desired state.

./green build
./green create --dry-run
./green create
./green describe
./green rehearse

What create owns

One t3.small in us-east-1a inside a dedicated VPC, a security group that opens 22 alone, the machine keypair, the OpenTofu state bucket redis-aws-state-251213589273-us-east-1 and the backup bucket redis-aws-backup-251213589273-us-east-1. Delete removes all of it, buckets included.

Connecting

ssh -L 6379:127.0.0.1:6379 redis-aws
REDISCLI_AUTH=$(ssh redis-aws sudo -n cat /etc/redis/secrets/password) redis-cli -p 6379

Recovery

A restart recovers from the append-only file, proven on every converge. RDB sets land every six hours under redis-aws/redis/ in the backup bucket with completion markers; ./green rehearse restores the newest into a scratch instance of the pinned image, reads the smoke key back, and writes .colors-recovery-verified.
